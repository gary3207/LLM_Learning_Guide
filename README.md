# 📘 작은 모델부터 배우는 LLM · MLOps

**Linux 환경 준비부터 텍스트 분류·평가·토큰 생성까지, 코드를 실행하며 원리를 익히는 한국어 학습 가이드입니다.**

작은 예제로 **데이터 → 학습 → 저장 → 추론 → 평가**의 흐름을 이해한 뒤, 문장을 한 토큰씩 생성하는 과정과 문맥의 역할을 살펴봅니다. 완성된 챗봇을 바로 만드는 대신, 각 계산과 출력의 의미를 설명할 수 있는 것을 목표로 합니다.

## 🛠️ 실습 환경과 실행 위치

- 환경 예시: **Ubuntu + Python 가상환경 + PyTorch**.
- GPU 계산과 분류기 학습 예제는 NVIDIA CUDA 환경을 사용합니다. 다음 토큰 예측과 두 토큰·세 토큰 문맥 모델은 CPU에서 실행하는 코드입니다.
- 기본 실습 폴더는 `~/llm-lab/source`입니다. 이 저장소의 장별 `source/` 경로와 구분합니다.
- 체크포인트를 저장하는 코드는 파일 위치에 의존할 수 있습니다. **각 장에서 지정한 VM 경로·파일명으로 배치한 뒤 실행합니다.**
- 드라이버·CUDA·패키지 버전은 설치 환경과 지원 조합을 확인합니다. 특정 버전을 모든 환경에 그대로 적용하지 않습니다.

> [!WARNING]
> 코드를 한꺼번에 실행하지 마세요. 각 장의 선행 파일과 저장 경로를 확인하고 순서대로 진행합니다. 기존 체크포인트 보호 검사를 제거하거나, 재실행을 위해 원본 모델을 임의로 삭제하지 않습니다.

## 🔬 실행 예시와 해석

아래는 예제 데이터와 설정의 **참고 출력**입니다. 패키지·장치·난수 처리에 따라 loss와 예측이 달라질 수 있으므로, 동일한 숫자보다 계산 흐름과 검사 조건을 이해하는 것이 중요합니다.

| 실습 | 실행 예시 | 해석의 범위 |
|---|---|---|
| 데이터 분리 | train 10 / validation 4 / test 3 | 교육용 소규모 데이터; 운영 평가를 대표하지 않음 |
| 두 분류 모델 검증 | 정확도 모두 3/4, 75.0% | 동률일 때 미리 정한 보조 기준 적용 |
| 검증 loss 비교 | 원본 0.8041 / 보완 0.7280 | 이 예시에서는 보완 모델 선택 |
| 선택 모델 테스트 | 3/3, 100.0% / loss 0.2959 | 세 문장 결과만으로 다른 오분류 해결을 단정할 수 없음 |
| 한 토큰 모델 | 학습 쌍 9/9 / 최종 loss 0.0055 | 학습 문장 재현이지 일반화 성능은 아님 |
| 두 토큰 모델 | 학습 쌍 6/6 / loss 1.6644 → 표시값 0.0000 | 반올림된 표시값이며 정확한 0을 뜻하지 않음 |
| 세 토큰 모델 | 학습 쌍 8/8 / loss 2.3490 → 표시값 0.0000 | 학습 쌍 적합 결과; 복원·생성은 별도 검사 |
| 문맥별 생성 | `gpu status failed`, `network status healthy` / `<eos>` 종료 | 복원·문맥 이동·종료·길이 제한 확인 |
| 세 토큰 문맥별 생성 | `gpu current status failed`, `network current status healthy` / `<eos>` 종료 | 저장 모델 복원·마지막 세 토큰 입력·양쪽 길이 제한 검사 통과 |

> [!IMPORTANT]
> 검증 문장 중 일부는 앞선 오류 분석에서도 사용합니다. 이 구성은 **평가 절차를 배우는 예제**이지, 완전히 새로운 문장에 대한 엄격한 블라인드 평가가 아닙니다. [평가 설계의 한계](04-evaluation.md)를 함께 읽으세요.

## 🌱 다루는 범위

선형 분류기와 고정 길이 문맥 모델로 학습·저장·복원·평가·생성을 익힙니다. 이 모델들은 Transformer나 대화형 LLM이 아닙니다. Attention 입문은 QKV 선형 변환·비중 계산·Value 가중합·causal mask·위치 표현에서 시작해 어휘 출력·loss·기울기·출력층 학습 루프와 자동 미분 비교를 다룹니다. 마지막 연결 실습은 고정 입력에서 QKV와 어휘 출력 행렬을 함께 한 번 갱신합니다. 09장은 고정 입력의 단일-head Attention에 잔차·LayerNorm·FFN을 붙인 작은 블록을 한 번 갱신합니다. 10장은 학습되는 토큰·위치 임베딩을 연결해 두 예문 모든 입력 위치의 다음 토큰 정답을 학습합니다. 11장은 같은 작은 블록 기반 모델을 별도 저장하고 새 프로세스에서 복원해 학습 예문을 반복 생성합니다. 엄격한 독립 최종 평가와 RAG·LoRA·서빙·Kubernetes는 후속 범위입니다.

12장은 모델을 바꾸지 않고 새 입력의 반응을 정성적으로 관찰합니다. 13장은 합성 정답과 형식별 분리로 마지막 상태 위치를 평가합니다. 소수 예제의 진단 평가이며 넓은 일반화나 모델 선택의 완료를 뜻하지 않습니다.

14장은 원본을 보존하고 복사본 둘을 같은 조건으로 추가 학습해 데이터 표현 보완을 비교합니다. 이전 test는 개발용으로 구분하며 독립 최종 평가·문장 생성 유지 검증은 포함하지 않습니다.

15장은 보완 후보 재현·생성 회귀 확인·별도 저장·새 프로세스 복원을 한 흐름으로 묶어 작은 모델 실습을 마무리합니다. 상태 정답 개선과 생성 유지 실패, 재현 성공과 품질 개선을 구분합니다.

16장은 사전학습된 SmolLM2-135M-Instruct와 토크나이저를 불러와 CPU에서 질문 토큰화·대화 템플릿·마지막 위치 점수·greedy 응답 생성을 관찰합니다. 로컬 다운로드·추론·캐시 오프라인 재실행을 검증한 예제이며 새 학습이나 사실성 평가가 아닙니다.

17장은 같은 모델을 두 합성 질문·응답으로 SFT하고, 학습 질문과 표현 변경 probe에서 기본 모델 대비 loss·생성을 비교합니다. 원본을 보존하며 별도 저장·새 프로세스 복원까지 실행합니다. 전체 파라미터 CPU 학습의 작은 예제이며 독립 최종 평가·넓은 생성 회귀는 포함하지 않습니다.

18장은 같은 원본·데이터·SGD 설정에서 q/v rank4 LoRA만 학습하고 작은 어댑터를 저장·복원합니다. CPU 검증과 별도 A10 CUDA 실행 로그에서 loss는 낮아져도 정답을 생성하지 못한 결과와 복원 성공을 함께 확인합니다. 학습 대상 수 감소와 품질·GPU 메모리·속도를 구분합니다. QLoRA는20장으로 연결하며 RAG·서빙은 후속 범위입니다.

19장은 기존 원본·SFT·LoRA를 재학습 없이 같은 평가 장치·생성 조건으로 실행하고, 학습 질문·기존 probe·추가 진단의 정답률과 응답/eos loss를 따로 집계합니다. 문항별 생성·오류 분류와 설정을 JSON으로 저장합니다. 미학습 fixture의 CPU 코드 검증과 별도 CUDA 학습 후보 평가를 구분합니다. CUDA 추가 진단은 원본0/4·SFT3/4·LoRA0/4이며, SFT의 잘못된 상태 라벨과 LoRA의 loss 감소/정답 수 유지도 수록합니다. 독립 최종 평가·자동 모델 선택은 포함하지 않습니다.

20장은 같은 원본을 NF4·이중 양자화로 로딩하고 q/v rank4 어댑터만 새로 학습·저장·복원합니다. 실제 CPU 검사와 별도 A10 CUDA 로그 모두 원본/양자화 상태 유지·어댑터 저장·복원 통과를 확인했지만 loss 감소가 한 단어 정답 생성으로 이어지지는 않았습니다. 연산은 float32인 교육용 구성으로 논문 전체 재현·성능 벤치마크와 구분합니다. 기존 후보는 유지하고 서빙은 다음 묶음으로 남깁니다.

21장은 저장한 QLoRA를 읽기만 하고 Python 표준 HTTP 서버로 요청·응답을 연결합니다. 같은 VM의 두 터미널에서 health와 두 생성 요청을 보내고 Ctrl+C로 종료합니다. CPU 미학습 fixture의 코드 검사와 별도 CUDA HTTP200 실행 예시를 구분합니다. CUDA 응답은 입력41·40토큰/새8토큰씩이지만 한 단어 정답 생성은 실패했으며, API 성공과 품질을 구분합니다. 외부 공개·운영 배포·동시 처리·품질 개선은 포함하지 않습니다.

22장은 같은 저장 QLoRA를 측정 옵션으로 호출해 워밍업과 반복 측정을 구분하고, HTTP 지연·동기화한 생성 시간·실제 토큰/초·CUDA allocator 메모리를 기록합니다. CPU 미학습 fixture의 실제 HTTP/집계/저장 검사와 A10 CUDA 성능 측정을 구분합니다. TTFT·동시 부하·재학습·외부 공개는 포함하지 않습니다.
