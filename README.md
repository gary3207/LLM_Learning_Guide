# 📘 작은 모델부터 배우는 LLM · MLOps

**Linux 환경 준비부터 텍스트 분류·평가·토큰 생성까지, 코드를 실행하며 원리를 익히는 한국어 학습 가이드입니다.**

작은 예제로 **데이터 → 학습 → 저장 → 추론 → 평가**의 흐름을 이해한 뒤, 문장을 한 토큰씩 생성하는 과정과 문맥의 역할을 살펴봅니다. 완성된 챗봇을 바로 만드는 대신, 각 계산과 출력의 의미를 설명할 수 있는 것을 목표로 합니다.

## 🛠️ 실습 환경과 실행 위치

- 환경 예시: **Ubuntu + Python 가상환경 + PyTorch**.
- GPU 계산과 분류기 학습 예제는 NVIDIA CUDA 환경을 사용합니다. 다음 토큰 예측과 두 토큰·세 토큰 문맥 모델은 CPU에서 실행하는 코드입니다.
- 기본 실습 폴더는 `~/llm-lab/source`입니다. 이 저장소의 장별 `source/` 경로와 구분합니다.
- 체크포인트를 저장하는 코드는 파일 위치에 의존할 수 있습니다. **각 장에서 지정한 VM 경로·파일명으로 배치한 뒤 실행합니다.**
- 드라이버·CUDA·패키지 버전은 설치 환경과 지원 조합을 확인합니다. 특정 버전을 모든 환경에 그대로 적용하지 않습니다.

> [!WARNING]
> 코드를 한꺼번에 실행하지 마세요. 각 장의 선행 파일과 저장 경로를 확인하고 순서대로 진행합니다. 기존 체크포인트 보호 검사를 제거하거나, 재실행을 위해 원본 모델을 임의로 삭제하지 않습니다.

## 🔬 실행 예시와 해석

아래는 예제 데이터와 설정의 **참고 출력**입니다. 패키지·장치·난수 처리에 따라 loss와 예측이 달라질 수 있으므로, 동일한 숫자보다 계산 흐름과 검사 조건을 이해하는 것이 중요합니다.

| 실습 | 실행 예시 | 해석의 범위 |
|---|---|---|
| 데이터 분리 | train 10 / validation 4 / test 3 | 교육용 소규모 데이터; 운영 평가를 대표하지 않음 |
| 두 분류 모델 검증 | 정확도 모두 3/4, 75.0% | 동률일 때 미리 정한 보조 기준 적용 |
| 검증 loss 비교 | 원본 0.8041 / 보완 0.7280 | 이 예시에서는 보완 모델 선택 |
| 선택 모델 테스트 | 3/3, 100.0% / loss 0.2959 | 세 문장 결과만으로 다른 오분류 해결을 단정할 수 없음 |
| 한 토큰 모델 | 학습 쌍 9/9 / 최종 loss 0.0055 | 학습 문장 재현이지 일반화 성능은 아님 |
| 두 토큰 모델 | 학습 쌍 6/6 / loss 1.6644 → 표시값 0.0000 | 반올림된 표시값이며 정확한 0을 뜻하지 않음 |
| 세 토큰 모델 | 학습 쌍 8/8 / loss 2.3490 → 표시값 0.0000 | 학습 쌍 적합 결과; 복원·생성은 별도 검사 |
| 문맥별 생성 | `gpu status failed`, `network status healthy` / `<eos>` 종료 | 복원·문맥 이동·종료·길이 제한 확인 |
| 세 토큰 문맥별 생성 | `gpu current status failed`, `network current status healthy` / `<eos>` 종료 | 저장 모델 복원·마지막 세 토큰 입력·양쪽 길이 제한 검사 통과 |

> [!IMPORTANT]
> 검증 문장 중 일부는 앞선 오류 분석에서도 사용합니다. 이 구성은 **평가 절차를 배우는 예제**이지, 완전히 새로운 문장에 대한 엄격한 블라인드 평가가 아닙니다. [평가 설계의 한계](04-evaluation.md)를 함께 읽으세요.

## 🌱 다루는 범위

선형 분류기와 고정 길이 문맥 모델로 기초를 익힙니다. 이 모델들은 Transformer나 대화형 LLM이 아닙니다. 세 토큰 문맥은 빈도 비교와 학습·저장·복원·생성 코드를 다룹니다. Attention 입문은 교육용 Q·K·V로 비중 계산과 Value 가중합을 연결한 뒤, 직접 정한 선형 변환으로 입력에서 Q·K·V를 만듭니다. 변환 계수의 실제 학습, Transformer·RAG·LoRA·서빙·Kubernetes는 후속 주제로 구분합니다.
